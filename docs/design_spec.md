# NODAL デザイン仕様 v3.9
（暗い版のみ。v3.9：公式フィード・脆弱性の機械翻訳表示、バックナンバー、記事公開日の表示を追加。v3.8：設定画面、上のバーの歯車、「先頭へ戻る」のフェードを約300msに、押したあとのフォーカス。v3.7：「先頭へ戻る」のフェード、スマホ下部の余白。v3.6：さがすの候補件数、「先頭へ戻る」の位置。v3.5：トップの並び、トップの枠の押せる範囲。v3.4：ジャンルの画像。v3.3：スワイプ、画像なしの枠、媒体名の例外、読了バー。v3.2：左メニューの段差、詳細の中央寄せ、媒体名の作り方、要点の出し方。v3.1：深刻度の英語表記、メニューの区分見出し、画面の文言）

アプリの表示名は **NODAL**（添え書き：Clarity in the Network.）。リポジトリ名やパッケージ名は変えない。

見本は `nodal-prototype.html`（1ファイルで動く試作）。値が食い違うときは、この文書を優先する。試作は表示・操作の確認用であり、仕様にない見た目や値を正としない。

v1（琥珀の案）は破棄。

## 1. デザイントークン

色・文字の大きさ・余白・角丸・動きは、すべてトークンとして一元管理する。部品や画面ごとに値を直接指定しない。CSS変数は1ファイルにまとめ、各コンポーネントは意味に対応するトークンだけを参照する。新しい値が必要な場合は、既存トークンの流用を先に検討する。

### 1-1. 色

| 変数 | 値 | 使う所 |
|---|---|---|
| `--bg` | `#0E0F0F` | 画面の地 |
| `--bar` | `#1B1E1B` | 上のバー（緑みを残す） |
| `--nav` | `#141516` | 下のメニュー、引用の箱 |
| `--surface` | `#18191A` | カード、入力欄 |
| `--surface-2` | `#202224` | 試してみる／確かめることの箱、ホバー |
| `--surface-3` | `#2A2D2E` | 画像の下地、頭文字の札 |
| `--ink` | `#ECECEA` | 見出し、本文、原文タイトル |
| `--ink-soft` | `#C4C7C5` | 長い本文、補助本文、訳文 |
| `--muted` | `#9DA19F` | 出典、日付、機械翻訳の印 |
| `--line` | `#2C2F30` | 区切り線、枠。行の区切りは既存の行区切り用トークンを使う |
| `--accent` | `#91A995` | ジャンル名、選択中、リンク |
| `--accent-strong` | `#A5B9A8` | 選択中の文字、ホバー |
| `--accent-wash` | `#293A31` | 選択中のメニューの地 |
| 深刻度 Critical | 文字 `#e08b78`／地 `#422d2a` | 深刻度ラベル |
| 深刻度 High | 文字 `#d6a36d`／地 `#3e3428` | 深刻度ラベル |
| 深刻度 Medium | 文字 `#c7b66b`／地 `#3c3928` | 深刻度ラベル |
| 深刻度 Low | 文字 `#91b7a8`／地 `#293a34` | 深刻度ラベル |

深刻度は色だけで区別せず、必ず文字のラベルも添える。`color-scheme: dark`、`theme-color` は `--bar` と同じ色。明るい版と切り替えボタンは作らない。機械翻訳に専用色は追加せず、印は `--muted`、訳文は `--ink-soft` を使う。

### 1-2. 文字

- 本文：DM Sans + Noto Sans JP（400/500/600/700）。ロゴの文字だけ Space Grotesk 600、字間 0.19em。
- すべてアプリに同梱する。外部の配信元から書体を読み込まない。
- ページ見出し：26〜34px／600。
- 詳細の見出し：24〜34px。
- 記事の見出し：16px／600（狭い画面では既存のモバイル用見出しトークン）。
- 本文：16px、行間2.0。
- 補助：12〜14px。**12px未満は使わない**。
- 機械翻訳の印：既存の補助小見出し相当の文字トークン。大文字化・アイコン化・バッジ化しない。
- 機械翻訳の訳文：翻訳専用の文字トークンを使い、色は `--ink-soft`。原文タイトルより視覚的に一段控えめにする。
- 見出しは `text-wrap: balance`、点数や件数は `font-variant-numeric: tabular-nums`。
- 英大文字の小見出しは使ってよい（既存の小見出し文字トークン、`--muted`、字間0.12em前後）。
- 見出しの上の飾りの札（線＋文字など）、文末の「→」、「・」でつないだ補助情報は使わない。

### 1-3. 余白・角丸・動き

- 余白、要素間隔、内側余白、角丸、線幅、影、アニメーション時間・イージングは共通トークンに集約する。
- 画面や部品のCSSに数値を直接書かない。ブレークポイントなどレイアウト判定に必要な幅も、レイアウトトークンとして一元管理する。
- v3.9 で足す部分(機械翻訳・バックナンバー・公開日)は、この決まりで書く。既存の画面の値をトークンへ移すのはフェーズ2で行う(2026-11-25 オーナー決定。フロントエンドは例外4つ以外を変えない K-048。課題 K-059)。v3.9で新設する値は、下記「1-4. v3.9で追加するトークン」だけとする。
- 動きは必要最小限。登場アニメはトップの最初の表示だけ。「先頭へ戻る」のフェードは約300ms。`transition: all` は使わない。
- `prefers-reduced-motion` を尊重し、対象となる動きを止める。読了バーは隠す。

### 1-4. v3.9で追加するトークン

既存の色は流用するため、新しい色トークンは追加しない。追加するのは訳文の文字サイズと原文との間隔だけ。

| トークン | 値 | 使う所 |
|---|---:|---|
| `--font-size-translation` | `13px` | 機械翻訳の訳文 |
| `--space-translation` | `4px` | 原文タイトルと機械翻訳行の間 |

上記以外の色・文字サイズ・余白・角丸・動きは既存トークンを使う。トークン名と値はCSS変数定義に置き、コンポーネント側に直接の値を書かない。

## 2. 骨組み

| 幅 | 配置 |
|---|---|
| 1101px以上 | 上のバー（72px）＋左メニュー（232px）＋中央（最大820px）＋右の列（280px） |
| 768〜1100px | 右の列を隠し、中央に「脆弱性ウォッチ」の帯を出す |
| 767px以下 | 上のバー（60px）＋横に流れるジャンルのタブ（トップ＋7ジャンル）＋下のメニュー（ホーム／公式情報／脆弱性／保存） |

- 左メニュー：GENRES（トップ＋7ジャンル）、OFFICIAL（公式のお知らせ、脆弱性）、LIBRARY（保存、バックナンバー）。区分見出しは英大文字の小見出しで、押せる項目と見間違えない大きさ・色にする（押せない見た目、上に余白）。項目は区分見出しより約16px右に下げ、段差で区分の範囲を示す（PCの左メニューだけ。スマホは横に流れるタブと下のメニューのまま）。
- バックナンバーはLIBRARY内の独立したナビゲーション項目とする。スマホの下部メニューには追加しない。スマホでは「保存」またはホームの日付導線からバックナンバーへ進める。
- 押せる物の高さは40px以上、主な操作は44px以上。
- 詳細の本文幅は最大660pxで、中央の領域の中で左右中央に寄せる。
- iPhoneの横幅では、記事本文・一覧の文字領域を優先し、翻訳行のために横スクロールを発生させない。
- 画面のコンセプトは「朝の情報番組」。テロップ、進行表、コーナーの切り替えを情報設計に使う。ただし、放送局の模倣や装飾的な番組セットにはしない。情報の優先順位と一覧の流れで番組らしさを表現する。

## 3. 共通表示・記事データ

### 3-1. 記事の日付

- 記事には、元データに基づく**公開日**を保持し、表示する。
- 公開日と、NODALが取得・更新した日時は別フィールドとして扱う。取得日時を公開日として表示しない。
- 公開日時がある場合は、アプリの日本語表示に合わせて `Intl.DateTimeFormat('ja-JP', …)` で整形する。日付だけのデータは日付として扱い、タイムゾーン変換で前日・翌日にずらさない。
- 時刻が元データにない場合、時刻を補って表示しない。公開日が不明な場合は「公開日不明」とし、取得日で代用しない(2026-11-25 オーナー決定)。
- 一覧では出典・ジャンルなどの既存メタ情報と同じ補助情報の階層で公開日を表示する。記事の見出しより目立たせない。
- 記事詳細では見出しの下、出典と並ぶメタ情報行に公開日を表示する。
- バックナンバーの日付は、**配信日**(その日のニュースとして届いた日。items.date)を基準に分類する。記事の公開日では分けない(2026-11-25 オーナー決定。1日分の配信を前後の日にばらさないため。公開日の無い記事も必ずどこかの日に入る)。取得日・更新日も基準にしない。
- 公式フィードの配信時刻・更新時刻は、従来どおりフィード側の時刻として表示し、記事公開日と混同しない。
- CVEの公開日も公開日として扱う。更新日が別に存在する場合は、必要に応じて「更新」と明示して区別する。

### 3-2. 媒体名・出典

- 出典は媒体名だけを短く出す（`--muted`、12〜13px）。
- 媒体名は元記事のhttps URLのホスト名から作る。先頭の `www.`／`docs.`／`blog.`／`news.` を外す（例：`docs.ollama.com` → `ollama.com`）。よく出るホストは表示名に置き換える。
- https URLが無ければジャンル名。外したあとが国の区分だけ（`co.jp`、`ne.jp`、`or.jp`、`ac.jp`、`go.jp`など）になるときは外さない（`docs.co.jp` はそのまま）。
- 頭文字の札は媒体名の最初の1文字を大文字にする（例：O）。公式のお知らせの札も同じく1文字。
- 画面の文言に「ネタ」「今朝」「放送」は使わない。「ニュース」「今日」を使う。

### 3-3. 機械翻訳データ

- 機械翻訳は、公式のお知らせと脆弱性情報の英語タイトルに対して、任意の日本語訳フィールドが存在するときだけ表示する。
- 翻訳は原文の代替ではない。原文タイトルを必ず残し、訳文を原文の下に置く。
- 翻訳がない、空文字、または翻訳処理に失敗した場合は、印・訳文の行・そのための余白を一切表示しない。
- 訳文はリンクにしない。原文タイトルがリンクの場合でも、訳文自体はリンク領域に含めない。行全体のクリック領域を広げる既存のリンク疑似要素を使う場合は、訳文をクリック対象と誤認させない実装にする。
- 表示は「機械翻訳」の印＋訳文を一つのまとまりにする。読み上げでも一つのグループとして扱い、「機械翻訳」と訳文を連続して一度だけ読み上げる。印だけを独立した読み上げ要素にしない。
- 訳文の印は枠なしの文字のみ。色は `--muted`。訳文は `--ink-soft`。紫系色、強いアクセント色、背景色、囲み、アイコンは使わない。
- 原文タイトルと翻訳行の間は `--space-translation`。印と訳文の間は既存の小さなインライン間隔トークンを使う。
- 訳文はすべての対象画面で1行表示とし、幅を超えた部分は末尾を省略記号で切る。折り返しや複数行への展開はしない。省略された全文は読み上げ時には取得可能な訳文として扱う。
- 訳文の文字サイズは `--font-size-translation`。最低文字サイズのルールを守る。
- 機械翻訳の印は訳文の出所を示すラベルであり、翻訳精度の保証や公式訳であることを意味しない。

## 4. 画面

### 4-1. トップ（ホーム）

- 「今日」を統合した画面。一番上にトップ（画像＋文章の大きな枠）を置く。
- 見出し「今日のニュース」は画面に出さず、読み上げ用の見出し（h1）としてだけ残す（日付は上のバー、件数はニュース一覧の見出しの横にあるため）。
- 続いて脆弱性ウォッチの帯1本（Criticalの件数と最新のCVE、CVSS。押すと脆弱性の一覧へ）、ニュース一覧（全件、番号つきの行。リードを1行）。
- 数字タイルを並べる冒頭は作らない。
- トップにはバックナンバーへ移動できる日付導線を置く。現在日付を表示し、押すとバックナンバーの日付選択へ移動する。導線は上のバーの日付表示と競合させず、既存の情報階層に収める。
- トップ右の欄には脆弱性ウォッチ、公式のお知らせ、保存したニュースを置く。公式のお知らせは原文タイトルの下に翻訳行を表示できる。
- 右欄の公式お知らせは幅が限られるため、製品名・原文タイトル・翻訳行の順で縦に並べる。原文と訳文はそれぞれ1行省略表示とし、時刻は既存の補助情報として残す。翻訳がない場合は原文と時刻だけを表示する。
- 768〜1100pxでは右欄を隠し、既存仕様どおり脆弱性ウォッチの帯を中央に出す。

### 4-2. ジャンル

- そのジャンルのニュースの一覧。
- プロダクトだけ、下に公式のお知らせと種類の絞り込み（すべて／リリース／サポート終了／試験／障害）。
- ニュース一覧の各記事に公開日を表示する。日付は公開日フィールドを使う。

### 4-3. 公式のお知らせ

- RSSをそのまま並べる。「AIによる要約はしていません」と明記。
- ベンダーのロゴは使わず、頭文字の札。
- 英語のタイトルに日本語訳がある場合、FeedRowの原文タイトル直下に「機械翻訳」＋訳文を1行で表示する。訳文はリンクにしない。
- 訳文がない記事は従来どおり原文だけを表示する。翻訳行用の空白を残さない。
- 製品名・種類・配信時刻など既存の情報階層は維持する。翻訳表示によって種別や時刻を押し下げすぎない。
- フィードの配信時刻と記事の公開日が異なる場合は、データの意味に合わせてラベルを付けて区別する。

### 4-4. 脆弱性

- 深刻度ごとの件数カードが、そのまま絞り込みボタン（もう一度押すと解除）。
- カードにCVE番号、製品、CVSS、状況。
- 個別の画面あり。
- 英語の脆弱性タイトルがある場合、VulnCardの原文タイトル直下に「機械翻訳」＋訳文を1行で表示する。
- 脆弱性詳細画面でも、CVE番号・深刻度などの識別情報の後、脆弱性の原文タイトル直下に同じ翻訳行を表示する。原文がタイトルとして存在しないデータでは、翻訳だけをタイトルのように表示しない。
- 訳文がない場合は原文だけを表示し、翻訳用の空白を残さない。
- 公開日をカードと詳細に表示する。CVEの公開日と更新日を混同しない。
- CVEの要約・影響・修正状況は翻訳タイトルとは別の情報として扱う。

### 4-5. ニュースの詳細

- ジャンル名、見出し、出典と公開日、保存ボタン、画像（ない時は出典の頭文字の札を出典の横に小さく）、要点（短い箇条3行。「AIがまとめた」と明記。データが配列なら箇条、文字列1つなら段落のまま出し、文を切って箇条を作らない）、元記事の抜粋（原文を手を加えずに引用）、試してみる、気をつけること、出典と元記事へのリンク、評価4つ、メモ、前後のニュース。
- 上のバーの下端に読了バー。
- 見出しの下のリード文と「このニュースについて」の欄は、今の位置のまま置く。
- 記事の公開日を出典と同じメタ情報行に表示する。取得日時を代わりに表示しない。
- 前後のニュースへは横のスワイプで移れる（7章）。
- 前後のニュースは、開いた一覧の並びの中で決める：ジャンルの一覧から開いたらそのジャンルの一覧（`itemsInGenre` の順）、保存の一覧から開いたら保存の一覧の順、バックナンバーから開いたらその日のバックナンバー一覧の順、それ以外（トップ・さがす・右の欄など）は同じ日の全ジャンル。どの一覧から開いたかはURLに持たせる（例：`#/item/<id>?from=genre:<ジャンルのid>`、`#/item/<id>?from=saved`、`#/item/<id>?from=archive:<YYYY-MM-DD>`）。
- 「一覧に戻る」は開いた一覧へ戻る。前後が無いときの表示（前は押せない文字、次の代わりに「一覧に戻る」）は変えない。
- 「一覧に戻る」のリンクは1行に独立させ、その下にジャンル名を置く（詰めて並べない）。
- 「試してみる」の見出しは、ジャンルがセキュリティニュース・プロダクトのときは「確かめること」にする。

### 4-6. 保存

- 保存したニュースの一覧。名前は全ジャンル共通で「保存」。
- 記事ごとの公開日を一覧に表示する。
- 保存一覧から詳細を開いたときは、保存一覧内の並びで前後の記事を決める。

### 4-7. さがす

- ニュース、公式のお知らせ、脆弱性を分けて表示。
- 入力中は候補（ニュース／公式のお知らせ／脆弱性／ジャンル）を出す。候補は分類ごとに最大3件（4分類で最大12件）。
- 公式のお知らせの候補は外部リンクにせず、その検索語の結果の画面（`#/search?q=`）へ移す。
- ↑↓・Enter・Escの案内はPCだけに出す。
- 検索結果にも公式お知らせと脆弱性の翻訳行を適用する。記事公開日を表示する。
- バックナンバーの日付を検索対象にする必要はない。過去記事の検索結果から開く場合も、詳細の戻り先と前後移動の規則を維持する。

### 4-8. バックナンバー（v3.9）

- 過去の日に配信されたニュースを読むための独立した画面を追加する。画面名は「バックナンバー」。
- 画面上部にページ見出し「バックナンバー」と日付選択を置く。初期状態は直近の過去日（今日を除く、記事が存在する最も新しい日）を選択する。
- 日付は配信日を基準に新しい順で選べる。範囲は読み込んだ分(最大 1,000 件。基本設計 8.3)。記事が存在しない日を選んだ場合は、空状態として「この日のニュースはありません」と表示する。別の日付へ移動できる導線を残す。
- 選択した日付の記事を、その日の配信の並び(sort_order。トップと同じ進行順)に並べる。記事一覧はトップと同じ番号つきの行を基本とし、記事タイトル、リード、出典、公開日を表示する。
- 同じ日に公開された記事が複数ジャンルにまたがる場合は、ジャンルをまたいで一つの一覧にまとめる。ジャンル名は各記事の補助情報として表示する。
- 公式のお知らせ・脆弱性をバックナンバーに混在させない。バックナンバーはニュース記事を対象とし、公式フィードと脆弱性はそれぞれの専用画面で扱う。
- 日付選択はURLに反映する（`#/archive/<YYYY-MM-DD>`）。再読み込み、共有、ブラウザーの戻る／進むで選択日を復元できる。
- バックナンバーから記事詳細を開いたときは、選択日と一覧の並び順をURLに保持する。詳細の「一覧に戻る」と前後移動は同じ日付のバックナンバー内で行う。
- スマホでは下部メニューを増やさない。ホームの日付導線、保存画面内の案内、または既存のナビゲーション領域から到達できるようにする。PCでは左メニューのLIBRARYに置く。
- 初回データ取得中、通信エラー、記事0件の状態を用意する。日付を選べない状態でも空画面にせず、状態を説明する。

### 4-9. 設定（v3.8）

- 上のバーの右端（さがすの右）に歯車のボタンを1つ置く（どの幅でも上のバーに出す。下のメニュー・左メニューには項目を足さない）。アイコンだけのボタンなので `aria-label="設定"`、押せる範囲は44px以上。ホバーは色と枠だけ変え、回したり動かしたりしない。押すと設定の画面（`#/settings`）。
- 画面の作り：上に「戻る」のリンク（1行に独立）、ページ見出し「設定」。その下にカード（`--surface`、枠 `--line`）を1枚置き、中を区分で区切る（区切り線 `--line`）。
- 区分の見出し：英大文字の小見出し＋番号（`ACCOUNT / 01` のように。2章の英大文字の小見出しの決まり）と、その下に日本語の見出し（16px／600）。右に小さな札を置いてよい（12px、`--muted`、枠 `--line`）。見出しの上の飾りの線は付けない。
- **ACCOUNT / 01 アカウント**：Supabaseモードでは、ログイン中のメールアドレスと、文字のボタン「ログアウト」。見本のデータのとき（環境変数が無いとき）は「ログインなし（見本のデータ）」と出し、ログアウトは出さない。ログアウトは「保存」の画面からここへ移す（「保存」の画面からは消す）。
- **THIS DEVICE / 02 この端末のデータ**（札 `DEVICE ONLY`）：行の一覧で、保存・評価・メモの件数と、ニュースの読み込み元（Supabase／見本）を出す。その下に、危ない操作のボタン「この端末のNODALデータをすべて削除」（枠と文字をCriticalの文字色、地は透明。文末に→を付けない）。押したら確認（「この端末の保存・評価・メモをすべて削除します。元に戻せません。」）を挟み、はいのときだけ消す。消すのはアプリが端末に置いた保存・評価・メモ（とアプリの小さな設定）だけで、ログインの情報は消さない（ログインしたまま）。消したら件数を0にし、`aria-live` で「この端末のデータを削除しました」と知らせる。ボタンの下に説明「ログアウトしても、このデータは消えません。この端末にだけあります。」（12px、`--muted`）。
- **ABOUT / 03 このアプリについて**：ロゴ（印＋NODALの文字）と添え書き、説明文1行。行の一覧で「版」（package.jsonの版と、配信のときのコミットの先頭7文字。手元ではlocal）、「最後に読み込んだ時刻」（ニュースの読み込みに成功した時刻。まだなら「—」。`Intl.DateTimeFormat('ja-JP', …)`）。
- 文字は12px未満を使わない（行の名前と値は13〜14px、説明は12px）。色は1章の変数だけ。外部の書体を読まない。
- 作らないもの：ニュースの読み方の設定（起動時の画面、ホームのジャンル、一覧の間隔、画像・要約・動きの切り替え）、表示テーマの切り替え、「保存だけ消す」「設定を初期状態に戻す」のボタン。
- 元の案：`request7/design/nodal-news-app_chatgpt_settings.html`（ChatGPT。左メニューと下のメニュー、文字の大きさ、色の値、02の区分はこの仕様が正）。

## 5. 画像

- 記事の画像は `filter: saturate(.62) brightness(.82)` で色調をそろえる。
- 画像の使い分け（元記事の画像を最優先。記事ごとに絵を生成したり素材を探したりはしない）：

| 場所 | 元記事の画像があるとき | 無いとき |
|---|---|---|
| トップの大きな枠 | その画像 | ジャンルの画像 |
| ニュース一覧の行 | 小さなサムネイル | 画像の場所を取らず文字だけ（出典の横に小さな札） |
| 詳細 | その画像 | ジャンルの画像 |
| バックナンバーの行 | 小さなサムネイル | 画像の場所を取らず文字だけ（出典の横に小さな札） |

- ジャンルの画像：7ジャンルに1枚ずつ用意してアプリに同梱する（作風・大きさ・置き場所は別途決めてから追記する）。用意できるまでは、トップの枠も画像の場所を取らず文章だけで全幅にする。
- 元記事の画像の取得は配信データ側の課題（K-042案）。
- `img` には `width` `height` `alt` を付け、画面外は `loading="lazy"`。

## 6. ロゴ

`logo/` にあるSVGを使う（元画像を目で写したもの。正式版が来たら差し替える）。

- `nodal-mark.svg`：印だけ。上のバーではこの形を、`--ink` と `--accent` で描く。

## 7. 実装で必ず守ること

試作は簡略にしている。以下を本番実装で必ず守る。

- 記事の行は、見出しを本物のリンク（`a`）にする。行全体を `div` や `article` のクリックにしない。押せる範囲は、リンクの疑似要素（`::after` で `inset:0`）で行全体に広げる。保存ボタンはリンクの外に置き、疑似要素より上（`position:relative; z-index:1`）にする。トップの大きな枠も同じ作りにし、枠全体を押せるようにする。
- 翻訳行は原文タイトルと同じリンク要素に含めない。読み上げは「機械翻訳」ラベルと訳文を一つのまとまりとして扱う。翻訳がない場合はDOMにも翻訳用の空要素を出さない。
- ジャンル、絞り込み、検索語、バックナンバーの日付はURLに反映し、再読み込みや「戻る」で元の表示に戻れるようにする。
- 日付は `Intl.DateTimeFormat('ja-JP', …)` で整形する。日付のみの値を不用意にUTC日時へ変換しない。
- 公開日と取得日時を別フィールドで保持し、画面上でも意味を区別する。
- `:focus-visible` の枠を消さない。`prefers-reduced-motion` を尊重する。`transition: all` を使わない。
- アイコンだけのボタンに `aria-label`、飾りのSVGに `aria-hidden="true"`、通知は `aria-live="polite"`。
- スマホの検索は、虫めがねのボタンを押すと欄が開く形にする（試作は狭い欄のまま）。
- メモは自動保存し、「メモを保存しました」と出す。
- 画面の幅にかかわらず、翻訳行は横スクロールを発生させない。省略表示された訳文も、アクセシビリティ上は全文を利用可能にする。
- URLからバックナンバーの日付・戻り先を復元できるようにする。ブラウザーの戻る／進むで画面状態が壊れないよう、履歴を適切に管理する。
- 翻訳テキストは未信頼データとして扱い、HTMLとして挿入しない。エスケープしてテキストとして描画する。
- 公開日が不明な記事に、取得日を公開日として表示しない。

## 8. 共通の状態・動き

- 用意する状態：0件、画像なし（頭文字の札）、画像の読み込み失敗（同じ札に差し替え）、読み込み中、通信エラー。
- 「先頭へ戻る」ボタンは1画面分スクロールしてから出す（どの幅でも出す）。767px以下では下のメニューに隠れないよう、その上（下のメニューの高さ＋`env(safe-area-inset-bottom)`＋余白）に出す。
- 1100px以下では、一番下までスクロールしたときにメモ欄の右下のつまみや「前のニュース／次のニュース」のボタンがこのボタンに隠れないよう、画面の下にボタンの分の余白を足す（ボタンの位置と欄の作りは変えない）。
- ボタンは出るとき・消えるときに不透明度だけを約300msで変えてフェードする（登場アニメをトップの最初の表示だけにする決まりの例外。v3.7の200msは短いので変更）。
- 押して先頭へ戻ったら、その画面の最初の見出し（h1。読み上げ用だけの見出しでもよい）にフォーカスを移す（ボタンが消えてフォーカスが行方不明にならないように）。消えている間は押せず、キーボードのフォーカスも当たらず、読み上げにも出ない。
- 登場アニメはトップの最初の表示だけ。
- 押すと縮む動き、読了バー、候補が開く動き、「先頭へ戻る」のフェード、スケルトンの光沢、スワイプの動きは `prefers-reduced-motion` で止める（読了バーは隠す。スワイプはアニメーションなしで切り替える）。
- 見本は改善案v3（https://claude.ai/artifact/GKevgnuLr2NCXNis12uNX7）。
