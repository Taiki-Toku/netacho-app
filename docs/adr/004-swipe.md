# ADR-004 詳細のスワイプ(指に合わせて動かす方法)

- 日付:2026-11-17
- 状態:採用(ベータ版)

## 背景
依頼 5-3b(仕様 v3.3 の 7 章)。詳細の画面で、記事を指の動きに合わせて横に動かし、前後のニュースへ移る。
前の作り(指を離した位置の差だけを見る)は、指に付いてこない・離した瞬間に記事が差し替わる・縦のスクロールと取り合う、の3つが問題だった。
一方、コーディング規約は「インラインの style を使わない」(あとで厳しい CSP を入れるため)。指の位置は1コマごとに変わるため、クラスの切り替えだけでは表せない。

## 選択肢
1. scroll-snap(横に並べてブラウザーに任せる):オーナーの判断で採らない(URL・履歴・「戻る」の動きを変えない)。
2. React の `style` 属性で `transform` を書く:規約に反する。1コマごとに React の描画も走る。
3. 要素の CSS 変数(`--swipe-x`)を DOM の API(`element.style.setProperty`)で書き、`transform` と `transition` は CSS Modules に書く。
4. Web Animations API:指に付いてくる動きには向かない。試験の環境(jsdom)に無い。

## 決定
3 を採る(`src/lib/useSwipe.ts`、`src/screens/ItemScreen.module.css`)。

## 理由
- CSP の `style-src` が止めるのは HTML の `style` 属性と `<style>` の中身で、スクリプトから CSSOM を通して書く値は止めない。厳しい CSP を入れても動く。
- JS が書くのは数値から作った長さ(`123px`)1つだけ。外から来たデータは入らない。見た目の決まり(transform、時間、動きを減らす設定)は CSS とトークンに残る。
- React の描画を通さないため、指の動きのたびに画面全体を描き直さない。
- 規約の「インラインの style を使わない」の例外は、この1か所(`--swipe-x`)だけとする。

## あわせて決めたこと
- 縦か横かは最初の約 10px で決め、縦ならブラウザーのスクロールに任せる(`touch-action: pan-y`)。拡大の操作を止めないよう `pinch-zoom` も許す。
- 移るときは、記事を画面の外へ送り出してから URL を変える(今までどおり `navigate`。履歴に1つ積まれ、「戻る」で戻れる)。移った先の記事は反対側から入る。
- 読了バー(画面に固定)は、動かす枠の外に置く(transform の付いた要素の中では、固定の基準がその要素になるため)。
- 記事が横に出ても画面が横にスクロールしないよう、`.main` に `overflow-x: clip` を付ける。
- 動きを減らす設定では記事を動かさず、指を離した時点で切り替える。
