## 2. データ

### 2.1 読み込み方
- `local-data/items.json` があればそれを使う(本物のネタ。git に入らない)。なければ `fixtures/sample-items.json`(架空の見本)を使う
- ジャンルの一覧は `fixtures/genres.json`
- **本物のデータが、git とビルドの成果物(`dist/`)に入らないこと**。入らないことを確かめる方法も報告する
- データを読む所は1か所にまとめ、画面からは「ネタの一覧を返す関数」として使う。あとで Supabase に差し替えるため

### 2.2 ネタ1本の形(`fixtures/sample-items.json` と同じ)

| 項目 | 型 | 説明 |
|---|---|---|
| id | 文字列 | `YYYY-MM-DD-NN` |
| date | 文字列 | 放送日 `YYYY-MM-DD` |
| order | 数値 | その日の中の順番 |
| slot | 文字列 | 番組のコーナー(「取り組みに効く」「製品ニュース」「新着」「組み合わせ」「掛け算」「道具箱」など。**決まった値以外も来る**ので、そのまま表示する) |
| genre | 文字列か null | 主ジャンル。`fixtures/genres.json` の id。null は「未分類」 |
| title / lead / summary / tryit / caution | 文字列 | 空のことがある。summary は改行を含むことがある |
| categories / projects / tags | 文字列の配列 | 空のことがある |
| sourceUrl / sourceTitle | 文字列 | 空のことがある。**`https://` で始まる URL だけをリンクにする**。それ以外は文字として表示する |
| trust | 文字列 | 情報の確かさ(「公式」「報道」「個人ブログ・コミュニティ」「未確認」「提案」) |
| stars | `{hot, use, fun}` | それぞれ 0〜5 |
| rating | 文字列 | `hot`(刺さった)/`good`(いいね)/`meh`(微妙)/`no`(いらない)/空(未評価) |
| status | 文字列 | `interest`(気になる)/`plan`(試す予定)/`tried`(試した)/`adopted`(採用)/`skip`(見送り)/空 |
| memo | 文字列 | 空のことがある |

- データはすべて「信用しないデータ」として扱う。見本には、HTML のタグや `javascript:` の URL をわざと入れてある。文字のまま表示され、リンクにならないことを試験で確かめる
- 件数は今 75 本。500 本になっても一覧がもたつかない作りにする(REQ-N-02)

## 3. ジャンルのタブ(案。動く画面を見てから変える前提)

今日/仕事・自動化/エージェント/ローカルLLM/セキュリティニュース/プロダクト/脆弱性/VTuber・創作/ツール・業界

- 見え方の手本は、スマートニュースやグノシーのような、横に並んだタブを切り替える形
- タブの一覧と並び順は `fixtures/genres.json` から作る(コードに直接書かない。あとで変えるため)

## 4. デザイン

- コンセプトは「朝の情報番組」。テロップ、進行表、コーナーの切り替えといった番組の文法で画面を作る
- **AI が作ったように見える量産型の見た目にしない**(紫系のグラデーション、絵文字をアイコンにする、角丸カードの羅列、汎用フォントだけの画面など)。絵文字は、データの中にあるものを除き、画面の部品として使わない
- 色・文字サイズ・余白・角丸・動きは、デザイントークン(CSS の変数)として1か所で定義し、それ以外の値を書かない
- 主に iPhone で、片手で使う。主な操作(タブの切り替え、前後の移動、画面の切り替え)は画面の下半分に置く(REQ-N-03)。幅 390px を基準にし、PC の幅でも崩れないこと
- ダークモードに対応する(REQ-N-04)
- フォントは、本文は端末のフォント。見出し用に Web フォントを使いたいときは、先に案を示す(外部からの読み込みはしない)
- **最初に、デザインの方向を言葉と色・文字の見本で示して、承認を得てから画面を作る**。作り始めたあとの大きな見た目の変更も、先に案を示す

## 5. 技術の前提

- React + TypeScript(strict)+ Vite。Node の版は `.nvmrc`
- スタイルは CSS Modules。CSS-in-JS とインラインの style は使わない
- 依存パッケージは最小限にする。追加の前に、CLAUDE.md の決まりどおり承認を得る(最初のひな形に入る React・Vite・TypeScript・ESLint・Vitest は承認済み)
- 試験は Vitest と Testing Library。Playwright は、このベータ版では入れない(必要になったら提案する)
- `npm run lint`、`npm test`、`npm run build` が通ること(CI がこの3つを実行する)
- 開発サーバー(`npm run dev`)は、オーナーが別のシェルで起動する。画面の確認が必要なときは、起動を頼む

## 6. 進め方(区切りごとに、報告して止まる)

1. ひな形を作る(Vite + React + TypeScript、ESLint、Vitest)。デザインの方向の案を示す → **承認待ち**
2. データを読む所と、今日の放送の画面 → 報告
3. ネタの詳細(前後の移動、出典の安全な表示) → 報告
4. ジャンルのタブ → 報告
5. バックナンバーと、探す → 報告
6. 設定、ダークモード、全体の `design-check` → 報告

各区切りの報告には、次を入れる:何をしたか/なぜそう作ったか/危ない点/試験の結果/セキュリティの確認結果/オーナーに見てほしい画面と操作。

## 7. 合格の目安(ベータ版)

- `fixtures` のデータでも `local-data` のデータでも、6つの画面が動く
- 見本の「HTML のタグ入りの見出し」「`javascript:` の URL」「`http:` の URL」が、文字のまま表示され、リンクにならない(試験がある)
- `dangerouslySetInnerHTML` と `innerHTML` を使っていない(ESLint で禁止している)
- キーボードだけで主な操作ができ、画像やボタンに名前が付いている(jsx-a11y の指摘がない)
- `design-check` で、量産型の見た目の指摘が残っていない
- オーナーが画面を見て承認している
