## 付録:詳細設計 5.5・5.6
### 5.5 開き直しの読み直し・引っぱって更新・本文の欄(K-067。REQ-F-02・F-03、基本設計 8.3、K-048 の例外5・6。v0.11 2026-11-27)
今の状態(2026-11-27、netacho-app の main で確認):読み込みは起動時に1回だけ(src/data/DataProvider.tsx)。iPhone はホーム画面のアプリを止めたまま残すので、開き直しても読み込みがやり直されず、前日のデータのままになる【推測】。詳細の画面(ItemScreen.tsx)は、points があると summary を出さない(points が無いときだけ要点の欄に summary を出す)。

#### 5.5.1 開き直したら読み直す(①。不具合の直し)
- `visibilitychange` で表示に戻ったとき(`document.visibilityState === 'visible'`)と、`pageshow` の `persisted` が true のときに、前の読み込みに成功した時刻(loadedAt)から 30 分以上たっていれば、裏で読み直す
- 裏の読み直しは、画面を「読み込み中」にしない。今のデータを出したまま読み、成功したらデータと loadedAt を差し替える(今の画面・URL・スクロールの位置は変えない)。失敗したら今のデータのまま、トースト「最新に更新できませんでした」
- 読み直しの最中に、もう一度読み直しは始めない(1本だけ)
- DataProvider に、今の `reload`(画面を読み込み中にする。エラーからのやり直し用)とは別に `refresh`(裏の読み直し)を足す。状態に `refreshing: boolean` を足す

#### 5.5.2 引っぱって更新(②。例外5)
- スマホ(タッチ)だけ。ページの一番上(`window.scrollY === 0`)で下へ引いたときだけ始める。最初の約 10px で縦か横かを決め、横なら何もしない(詳細の左右のスワイプ useSwipe と取り合わない)
- 引いた量に合わせて、上のバーのすぐ下に表示を出す(最大 80px)。64px 以上で離すと `refresh` を呼ぶ。届かなければ戻す
- 表示の文言:引いている間「離すと更新」、更新中「更新中…」(aria-live="polite")。成功のトースト「最新に更新しました」、失敗は 5.5.1 と同じ
- 動きを減らす設定(prefers-reduced-motion)では、表示を動かさず、文言だけを出す
- 色・文字・余白・動きは既存のトークンだけ(新しいトークンを足さない)。見た目は design_spec に短い節を足す
- iPhone の標準の引っぱり(ページの弾み)とは重ねない:引いている間は `touchmove` を止める(引っぱりを始めたときだけ。ふだんのスクロールは止めない)
- PC は変えない(ブラウザの再読み込みで足りる)

#### 5.5.3 本文の欄(③。例外6)
- 詳細の並び:リード → 要点 → **本文** → 元記事の抜粋 → 出典 → このニュースについて
- 「試してみる/確かめること」と「気をつけること」の欄は、旧い記事でも出さない(読み手の環境に寄った一般論で、情報が増えないため。2026-11-27 オーナー決定。脆弱性の 5.6.3 と同じ扱い)。データの tryit・caution は消さず、画面で使わないだけ。labels.ts の tryitHeading は使わなくなるので消す
- 本文:points と summary の両方があるとき、見出し「本文」(h2。今の見出しと同じ形)の下に summary を出す。summary を改行(1つ以上)で分け、空でない段落ごとに `<p>`(React の文字の描画だけ)
- points が無いときは、今のとおり要点の欄に summary を出し、本文の欄は出さない(同じ文を2回出さない)
- AI の注記を、要点の欄の中から本文の後に移し、文言を「要点と本文は、元の記事をもとにAIがまとめたものです。」にする(本文が無いときは要点の後)
- 一覧の行・トップの大きな枠は変えない(リードだけ)

#### 5.5.4 変えないもの
- Supabase の問い合わせ(列・件数・並び)、CSP、sync/、下のメニュー、ほかの画面の並び

### 5.6 脆弱性の画面の直し(K-067 の④⑤⑥。REQ-F-04、K-048 の例外7。v0.12 2026-11-27)
今の状態(2026-11-27、netacho-app の main 80b7699 で確認):脆弱性のカード(VulnCard.tsx)は、CVE 番号の文字だけがリンクで、カードのほかの所を押しても開かない。脆弱性の詳細(VulnDetailScreen.tsx)には前後への移り方が無く、最後に決まり文句の「確かめること」がある。

#### 5.6.1 カード全体を押せる(④。不具合の直し)
- リンクは CVE 番号の `<a>` 1つのまま(読み上げの名前は CVE 番号のまま)。CSS でリンクの `::after` をカードいっぱいに広げ(カードを `position: relative`、`::after` を `position: absolute; inset: 0`)、カードのどこを押しても開く
- 訳の行(TranslationLine)はリンクの外のまま。カードの中にほかの押せる物は無い(足すときは `position: relative` と重なりの順で前に出す)
- フォーカスの枠はカード全体に出す(`.card:has(.link:focus-visible)`)。ホバーの枠は今のまま
- 同じ部品を使うトップ・さがすの脆弱性のカードも同じになる

#### 5.6.2 詳細で前後の脆弱性へ移る(⑤。例外7)
- 前後の順番は、脆弱性の一覧の順(vulnerabilities() の並び。新しい順)。一覧で深刻度を絞っていたときは、その絞りの中で移る
- そのため、一覧のカードのリンクに絞りを付ける:`#/vuln/<id>?sev=<critical|high|medium|low>`(絞りが「すべて」なら付けない)。router の vuln-detail に `severity: SeverityFilter` を足す(形の違う値は「すべて」)。トップ・さがすから開いたときは「すべて」
- 移り方はニュースの詳細と同じ:左右のスワイプ(useSwipe をそのまま使う)と、下の「前の脆弱性/次の脆弱性」のリンク(ニュースの詳細の pager と同じ部品の見た目)。端では押せない文字
- 「脆弱性の一覧に戻る」は、絞りを付けた一覧(`#/vuln?sev=…`)へ戻る
- 見つからない id・絞りに入らない id のときは、今の「見つからない」の表示のまま(前後は出さない)

#### 5.6.3 決まり文句の「確かめること」を消す(⑥)
- 詳細の最後の「確かめること」(どの脆弱性にも同じ文)を消す。読み手の環境に寄った一般論で、情報が増えないため(2026-11-27 オーナー決定)。ニュースの「確かめること」「試してみる」「気をつけること」も出さない(5.5.3)
