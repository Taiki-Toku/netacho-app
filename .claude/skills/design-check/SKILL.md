# デザイン点検(design-check)

HTMLページ・Webアプリ・アーティファクトを、2つの観点で点検して直すためのスキル。

1. **AIっぽさの検出**(Impeccable の品質基準と禁止リストを要約・翻案)
2. **使いやすさのルール監査**(Vercel Web Interface Guidelines を要約・翻案)

外部への読み込みは不要。このファイルだけで動く。

## 使い方

- 「このページを点検して」「AIっぽさをチェックして」「使いやすさを監査して」と言われたら使う。
- 対象が分からなければ、どのファイル(またはアーティファクト)を見るか1回だけ聞く。
- 見た目を大きく変える修正(配色・構成の作り直し)は、提案してユーザーの合意を得てから行う。小さな修正(コントラスト不足、ラベル漏れ、はみ出しなど)は、点検結果を示したうえでまとめて直してよい。

## 手順

1. **画面の性格を決める**(どの観点を重く見るかが変わる)
   - 行動させる画面(LP・宣伝):注目と行動のきっかけを最優先
   - 操作する画面(アプリ・ダッシュボード・ツール):見つけやすさ・一貫性・慣れた操作を最優先。個性は細部で出す
   - 読む画面(記事・手順書・ヘルプ):理解しやすい構造と読みやすさを最優先
   - 見せる画面(作品集・ギャラリー):作品を主役にし、UIは控えめに
2. **実際の表示を見る**。可能ならスマホ幅(390px前後)とPC幅(1100px前後)で画面を撮って確認する。コードを読むだけで判断しない。確認はまとめて行い、1つ直すたびに撮り直さない。
3. **下の「A. 品質の最低ライン」「B. AIっぽさの禁止リスト」「C. 使いやすさのルール」で点検する。**
4. **結果を出力する**(形式は最後の「出力の形式」)。
5. 合意を得たら修正し、もう一度表示を見て確認する。

## A. 品質の最低ライン(実物で確認する)

- **コントラスト**:本文とプレースホルダーは4.5:1以上、大きな文字は3:1以上。色付きの面の上の補助テキストは、その面の色味から作る(灰色にしない)。
- **影**:影にはずれ(オフセット)とぼかしを付ける。ずれのない色付きのにじみは飾りにすぎない。
- **余白**:関係の近いものは詰め、グループの間は広く空ける。見出しの上は下より広く空ける。
- **文字**:本文の1行は全角で約35〜40字(欧文なら65〜75字)に収める。見出しは折り返しを整える(text-wrap: balance)。文字の大きさと太さの段階をはっきり付ける。実際の文章ですべての画面幅を確認し、はみ出しを直す。
- **動き**:印象的な動きは1か所に絞る。全セクションに同じ登場アニメを付けない。動きを減らす設定(prefers-reduced-motion)を尊重する。
- **状態**:ホバー、押せない状態、読み込み中、エラー、空っぽの状態を用意する。キーボードでの操作とフォーカス表示も確認する。
- **ブラウザ任せの部分**:文字選択の色、カーソル、スクロールバー、フォーカスの枠、下線の位置、表の数字(等幅数字)も配色に合わせる。
- **言葉**:ボタンは押すと何が起きるかを書く(「送信」より「メモを保存」)。エラーは何が起きたかと直し方を書く。
- **漏れ**:依頼された要件がすべて画面にあり、数秒で見つけられること。

## B. AIっぽさの禁止リスト

依頼者がはっきり指定した場合は従ってよい。指定がないのにこれらを選んでいたら「決めていない」証拠なので、作り直す。

**画面の骨組み**
- 「アイコン+見出し+文章」の同じ大きさのカードを並べただけの構成。カードの中にカードは常に不可。
- 「大きな数字+小さなラベル+補足の数値+アクセント色」のお決まりの冒頭。
- 見出しの上に付ける英字の小見出し(アイブロウ)。**これは禁止**。見出しそのものに語らせる。
- 01 / 02 / 03 の連番。本当に順番に意味がある場合だけ使う。
- 中断する必要のない作業にモーダル(重ねて出す画面)を使うこと。

**表面の癖**
- グラデーションの文字。強調は太さか大きさで行う。
- 飾りとしてのすりガラス・ぼかし。
- カードや一覧の片側だけに付けた2px以上の色付きの縦線。
- ぼかしのないずらし影(box-shadow: 4px 4px 0)。ネオブルータリズムを選んだ場合以外は使わない。
- 中身の代わりに置いたミニグラフ・進捗リング・角丸の箱。
- 「技術っぽさ」の演出としての等幅フォント(コード・データ・計測値以外)。
- アイコン体系の代わりに使う絵文字や記号。アイコンは1つのライブラリかSVGで、線の太さをそろえる。
- ジャンルで決めた明暗(「開発ツールだから黒背景」など)。使う場面と時間帯で決める。
- よくあるAI配色:クリーム色の背景+高コントラストの明朝体+テラコッタ色、黒背景+蛍光グリーン1色、紫のグラデーション、何でもInterやシステムフォント。

## C. 使いやすさのルール

**アクセシビリティ**
- アイコンだけのボタンには aria-label を付ける。飾りのアイコンには aria-hidden="true" を付ける。
- 入力欄には label か aria-label を付ける。
- 操作は button、移動は a を使う(div にクリックを付けない)。
- 画像には alt を付ける(飾りなら alt="")。
- トーストなどの非同期の通知は aria-live="polite" で読み上げる。
- 見出しは h1→h2→h3 の順を守る。

**フォーカス**
- 操作できる要素には、見えるフォーカス表示を付ける(:focus-visible を使う)。
- outline: none にするなら、代わりのフォーカス表示を必ず用意する。
- 固定ヘッダーや重ねた画面が、フォーカス中の要素を隠さないようにする。

**入力フォーム**
- 正しい type(email、tel、url、number)と inputmode、autocomplete を指定する。
- 貼り付けを禁止しない。
- エラーは入力欄のすぐそばに出し、送信時は最初のエラーにフォーカスを移す。
- 送信ボタンは送信が始まるまで押せる状態にし、送信中は進み具合を示す。
- 保存していない変更がある状態で離れるときは警告する。

**動き**
- prefers-reduced-motion を尊重する。動かすのは transform と opacity を基本にする。
- transition: all を使わず、変える性質を列挙する。
- 5秒を超えて自動で動き続けるものには、止める手段を用意する。

**文字・文章**
- 「...」ではなく「…」を使う。読み込み中の表示は「読み込み中…」のように「…」で終える。
- 比べる数字には font-variant-numeric: tabular-nums を使う。
- 見出しには text-wrap: balance を使う。
- 能動態で書き、ボタンは具体的に書く(「続ける」より「APIキーを保存」)。

**中身の扱い**
- 長い文章でも崩れないようにする(折り返し・省略・単語の途中での改行)。flex の子要素には min-width: 0 を付ける。
- 空の状態を用意し、壊れた表示を出さない。
- 短い・普通・とても長い入力のすべてで確認する。

**画像・性能**
- img には width と height を指定する。画面外の画像は loading="lazy" にする。
- 外部フォントやCDNには preconnect を付ける。フォントは font-display: swap にする。
- 50件を超える一覧は、表示範囲だけ描く工夫をする(content-visibility: auto など)。

**移動と状態**
- タブや絞り込みの状態をURLに反映し、共有や再訪ができるようにする。
- 消すなどの取り返せない操作には、確認か取り消しの猶予を用意する。

**タッチ操作**
- touch-action: manipulation を指定する。
- モーダルや引き出し式の画面には overscroll-behavior: contain を指定する。
- スワイプなどのジェスチャーだけに頼らず、タップとキーボードの代わりを用意する。
- 端末の切り欠きには env(safe-area-inset-*) で対応する。

**ダークモード**
- 暗い配色には color-scheme: dark を指定する。theme-color を背景に合わせる。
- select などの部品にも、背景色と文字色を明示する。

**地域対応**
- 日付と数字は Intl.DateTimeFormat、Intl.NumberFormat で整形する。

**必ず指摘するもの**
- 拡大を禁止する指定(user-scalable=no、maximum-scale=1)
- 貼り付けの禁止
- transition: all
- 代わりのないフォーカス枠の消去
- クリックできる div や span
- サイズ指定のない画像
- ラベルのない入力欄、aria-label のないアイコンボタン
- 決め打ちの日付・数字の形式
- ジェスチャーだけの操作

## 出力の形式

日本語で、次の順に出す。前置きは不要。

1. **総評**(2〜3文):画面の性格、一番の強み、一番の弱み
2. **重要度順の指摘一覧**
   - 「重大」「中」「軽微」に分ける。
   - 各行は「場所(ファイル名:行番号、または画面の部位)— 問題 — 直し方」の形にする。
   - A・B・Cのどれに当たるかを添える。
3. **問題なしの観点**:1行で列挙する。
4. **次の一手**:修正をまとめて行ってよいか、見た目を大きく変える提案があるかを聞く。

技術用語は、初めて出るときに一言で言い換える(例:「CTA(行動を促すボタン)」)。
